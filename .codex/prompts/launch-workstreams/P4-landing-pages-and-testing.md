# P4 — Build vertical landing pages and an evidence-led test plan

**Recommended environment:** ChatGPT Work for research/messaging, then Codex for implementation  
**Priority:** Post-launch optimisation  
**Start when:** Baseline conversion tracking works and there is enough relevant traffic to learn.

## Copy this prompt into a new chat

```text
Act as the landing-page and conversion-experiment owner for Heutrix Labs. Work inside the current Heutrix repository. Read the control registers, current sector pages, approved offer, proof assets and the first 30 days of available traffic/lead data; use HEUTRIX-LABS-LAUNCH-REVIEW.md as historical context.

Goal: create focused landing experiences for materially different audiences and a disciplined testing backlog, while avoiding premature A/B tests on tiny samples.

Start with evidence:
1. Segment traffic and lead quality for allied health, disability providers and any proposed GP segment.
2. Review search/referral/LinkedIn intent, call notes, objections and no-fit reasons.
3. Decide whether each segment deserves a distinct landing page. Do not create a GP page until a specific GP workflow, fit criteria, delivery capability and proof plan are verified.

For each approved page, define:
- Target role, problem situation and buying trigger.
- Specific controllable outcome and relevant workflow examples.
- Flagship offer/entry path, scope and boundaries.
- Relevant demonstration/proof.
- CTA and qualification fields.
- Objections, FAQ and what happens next.
- Page-specific title, description, canonical and internal links.

Implement page(s) when authorised, preserving design consistency, accessibility, mobile behaviour, analytics and source capture.

Create a prioritised experiment backlog for headline/outcome, proof placement, CTA wording, call length/promise and qualification fields. For each hypothesis specify expected mechanism, primary metric, guardrail, segment, minimum evidence rule and decision criteria. With low traffic, favour sequential qualitative learning and call-note analysis over statistical claims.

Do not fabricate market data, conversion lifts or statistical significance. Do not run experiments that compromise truthful CTA wording or privacy.

Deliverables:
- Segment decision brief.
- Page-ready copy/structure and implemented pages where authorised.
- Analytics/QA requirements.
- Prioritised experiment backlog.
- Learning log template connecting page changes to qualified leads and calls.

Definition of done: each vertical page answers a distinct buyer situation, connects to the same coherent offer, tracks qualified outcomes, and every proposed test has a reason and evidence threshold rather than being a cosmetic experiment.
```
