# Heutrix Workflow Transformation

This is the primary implementation product for one bounded non-clinical workflow.

The current public method is:

`Diagnose → Triage → Build → Handover`

Diagnose the operational problem and map the workflow. Triage priorities, dependencies and scope. Build and test the simplest suitable improvement. Handover guidance, documentation and ownership to the team. Mapping, design and proof remain delivery activities within these four stages.

Before using it with a client, approve the start condition, included systems/roles, discovery effort, review points, testing method, refinement limits, training, acceptance, defects, change control, stabilisation, handover formats and post-project ownership.

The [flagship offer specification](../../02-market-and-offers/offers/offer-strategy-2026-09/02-flagship-offer-specification.md) is the current strategic source.

The [integrated architecture](../../02-market-and-offers/offers/offer-strategy-2026-09/06-integrated-offer-architecture.md), refined on 8 September 2026, clarifies process-only implementations, direct entry and AI dependencies. Diagnose within delivery does not mean a compulsory Diagnostics purchase. AI-enabled functions require appropriate controls before use; suitable existing client controls may suffice. Scope any additional test scenarios and measurement handover within validated effort and capacity.
