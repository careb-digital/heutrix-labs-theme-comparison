2. Existing legal artefacts used with this pack

Before exchanging non-public information. Use the Mutual Confidentiality Agreement where required. Do not invite sensitive information into a fit call.

Every paid Diagnostic. Issue and sign the Client Services Agreement plus the Workflow Diagnostic Order Form before work starts.

Any protected data or system access. Complete Data and System Access Authorisation before access is granted. The Diagnostic default remains no Personal Information or sensitive information.

Any AI use. Complete the AI Use Case Approval for one tool and one use case. No client data is approved for AI by silence.

Any scope, fee, timing, tool or data change. Use the Change Request before the changed work proceeds.

Acceptance and close. Use Deliverable Review and Acceptance, then Handover and Access Closure.

4. Control points that cannot be skipped

[ ]

Fit call notes contain no patient, participant, worker or other sensitive identifying information.

[ ]

The workflow is one operational workflow with an agreed start and end.

[ ]

The client understands the Diagnostic is evidence-led advice, not implementation, assurance or an audit.

[ ]

The Client Services Agreement and Workflow Diagnostic Order Form are signed before paid work starts.

[ ]

Payment and the agreed inputs are received before the delivery clock starts.

[ ]

Only the approved repository and approved named users are used.

[ ]

AI is not used with client confidential information or client data without a signed AI Use Case Approval.

[ ]

Every finding is traceable to evidence, an observation or an explicitly labelled assumption.

[ ]

The report, maps, opportunity list and presentation tell the same story.

[ ]

Acceptance, handover, access removal and data return/deletion are recorded at close.

6. File and record structure

  • Use a project ID in the form HTX-WD-[YYYY]-[NNN]-[CLIENT SHORT NAME].
  • Keep 01 Contract, 02 Client Inputs, 03 Working Papers, 04 Draft Deliverables, 05 Issued Deliverables and 06 Closeout as separate folders in the approved repository.
  • Use ISO dates in file names: YYYY-MM-DD. Use version labels v0.1, v0.2 for drafts and v1.0 for the accepted issue.
  • Never store credentials, unapproved personal information or raw recordings in the project folder.
  • Keep one evidence register and one decision log as the source of truth; do not create competing copies in email and personal notes.

7. Definition of done

[ ]

All contracted deliverables exist in editable and agreed issue formats.

[ ]

The current-state map covers the agreed start/end, roles, handovers, decisions and known pain points.

[ ]
