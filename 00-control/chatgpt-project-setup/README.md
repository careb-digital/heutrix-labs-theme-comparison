## How to set up each ChatGPT Project

1. In ChatGPT's Projects area, create a project using the exact recommended name in the relevant section.
2. Open its project instructions and paste the complete instruction block from that section. Each block includes the common Heutrix rules and its specific responsibilities; it can be used independently.
3. Add CURRENT-CONTEXT.md and the section's selected sources. Add the workstream guide and only the detailed files needed for the next task. For an index such as the Sales specification, add the relevant linked process section as well: the index does not contain every process detail.
4. For Finance, attach the current integrated workbook when doing calculations. For legal or Diagnostics reconciliation, attach the relevant native master and current export. A README describing a pack is not a substitute for its contents.
5. Start a fresh chat for one defined outcome. Use a title such as `03-01 | Live lead flow | Draft` and paste that numbered prompt.
6. Keep the result with the chat while it is being reviewed. Once adopted, save the final deliverable into its existing authoritative workspace location and refresh affected Project sources.
7. Archive completed chats when useful, while retaining the approved deliverable and decision evidence in the operating records. Avoid opening all 100 prompts as simultaneous unfinished work.

ChatGPT Projects can share uploaded files, project instructions and connected sources across their chats. A ChatGPT Project does **not** gain access to the local Heutrix folder from its name or a pasted path; upload or connect the required sources. Start separate chats for distinct outcomes. Pinning changes visibility, not access. These points follow [OpenAI's Projects documentation](https://learn.chatgpt.com/docs/projects).

The workflow above is a recommended operating design. This review did not inspect your ChatGPT Project instructions, source contents, sharing permissions or memory configuration. Check the options shown in your account instead of assuming a plan-specific file limit, connector or memory setting. For client separation, choose project-only memory if offered and appropriate, but do not treat memory settings as a substitute for approved access and information-handling controls.

## Source management without creating more drift

The repository remains the authoritative operating record. ChatGPT Projects receive dated, selected copies or explicitly connected sources. **Do not assume automatic synchronisation between local files and uploads, or between separate Projects.**

CURRENT-CONTEXT is an initial navigation and facts snapshot, not a new approval register. Record future decisions in the existing DECISIONS, VERIFIED-FACTS or relevant workstream register first. Then refresh this snapshot only when it helps project setup.

For each uploaded source, keep a small source list with original workspace path, source date/version, upload date and status. Use the section's source list as the starting manifest. Replace superseded uploads and clearly label historical references. Avoid giving the same old file a new date without checking its content.

Do not upload dependency folders, browser profiles, generated runtimes, entire repositories, all QA images, ZIP release packs or archived plans by default. Select the actual source, and one export when needed for inspection. Do not load CareBest, Glacier, Lensly or parent-folder portfolio context into every Heutrix project.

Treat 90-research-and-audits and 99-archive as on-demand evidence. Treat apps/internal-reports as historical analytical applications unless a task specifically needs them. Do not create separate active Projects for every archive, report, product or campaign week.

## Standard handoff between projects

At the end of an adopted decision or completed artefact, carry this concise record into Control and the affected project:

```text
Outcome:
Source and version/date:
Evidence used:
Status: draft / proposed / approved / issued / superseded
Owner decision and date, if any:
What changed:
Affected source files/projects:
Unresolved dependencies:
Verification performed and limitations:
Next action and completion evidence:
```

For code or native-file work, send the approved requirements to a Codex task with the precise target file/root and acceptance checks. ChatGPT's drafting context and Codex's file-editing context must not be confused. Do not claim that copying a handoff has implemented the change.
