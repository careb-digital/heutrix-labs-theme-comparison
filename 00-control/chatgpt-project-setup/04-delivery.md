## Ten prompts

Run one prompt per outcome-focused chat. The heading provides a suggested chat title. Each prompt uses this Project's instructions and sources. Complete dependent owner decisions before treating the resulting drafts as approved or live.

### 04-01 | Plan Diagnostics pack reissue

Compare the Diagnostics pack status with the current offer and sales rules. Produce a per-asset reissue checklist covering retired names, 30-minute wording, AUD 950, entity particulars and current boundaries. Request relevant native masters before claiming their contents are corrected.

### 04-02 | Define an independently useful Diagnostic

Specify the minimum Diagnostic outputs: bounded problem, current state, baseline or measurement plan, ranked bottlenecks, feasible options including no-build, recommendation and next scope. Create a synthetic findings outline and objective quality checklist.

### 04-03 | Make Transformation repeatable

Turn the flagship method into a stage plan with inputs, activities, outputs, review checkpoints and exit criteria. Show which prerequisites start the 2–4 week window and identify decisions needed before that timeline can be operationally supported.

### 04-04 | Define the AI Guardrails deliverables

Draft a bounded delivery specification for use-case inventory, information rules, human review, escalation, staff guidance and update ownership. Add buyer effort, acceptance evidence and exclusions. Do not position the service as regulatory, legal or clinical assurance.

### 04-05 | Write testable acceptance criteria

For a synthetic enquiry-to-service-start workflow, create functional, permission, exception, reporting and usability acceptance tests. Include expected results, evidence and client sign-off roles. Separate delivered behaviour from hoped-for savings or adoption.

### 04-06 | Resolve defects and changes

Draft an owner-reviewable decision table separating an in-scope defect, refinement, new requirement, client delay and third-party failure. Define proposed handling during the 30-day stabilisation period and questions for Legal and Finance.

### 04-07 | Test delivery capacity

Using founder availability and estimated project hours I supply, model overlapping engagements, reviews, testing, training and stabilisation. Identify the bottleneck and sustainable concurrent workload. If capacity is absent, provide the input template and labelled scenarios.

### 04-08 | Design launch and rollback

Prepare a reusable cutover plan for one bounded workflow, including synthetic testing, user acceptance, access checks, backup, parallel running, rollback triggers and responsible roles. Identify decisions that must be made per engagement.

### 04-09 | Complete handover standards

Create a handover checklist covering editable artefacts, administrator guidance, credentials transfer method, dependencies, licences, limitations, training, client ownership and support boundaries. Distinguish reusable Heutrix methods from client-specific materials for legal review.

### 04-10 | Close the rehearsal findings

Use the synthetic engagement findings from project 08 to prioritise template and process changes. Map each defect to its source, owner decision, revised artefact and retest. Do not declare delivery-ready while critical acceptance or data-handling gaps remain.
