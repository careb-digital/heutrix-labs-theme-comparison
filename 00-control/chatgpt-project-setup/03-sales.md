## Ten prompts

Run one prompt per outcome-focused chat. The heading provides a suggested chat title. Each prompt uses this Project's instructions and sources. Complete dependent owner decisions before treating the resulting drafts as approved or live.

### 03-01 | Design the minimum live lead flow

Use LEAD-HANDLING and LEAD-MAGNETS to specify a real request-to-inbox-to-pipeline flow. Compare a verified manual email route with a hosted-form route, identify receipt evidence and failure recovery, and produce a decision-ready implementation brief.

### 03-02 | Resolve booking operations

Turn the 15 owner questions in process section 12 into a compact decision sheet. Cover caller, backup, platform, availability, timezone, notice, cancellations, response scope and privacy. Provide provisional defaults and consequences without presenting them as agreed.

### 03-03 | Specify a usable minimum pipeline

Refine the existing pipeline into a minimal schema with stages, required fields, owner, next-action date, duplicate matching, loss reasons and retention rules. Include five synthetic records and entry/exit criteria for each stage.

### 03-04 | Rehearse the 20-minute fit call

Using the current call guide, simulate a disability-provider intake enquiry. Show timing, high-value questions, safe data boundaries, product routing and a concise written recommendation. Identify where the process becomes free consulting or overpromises scope.

### 03-05 | Test difficult qualification cases

Create eight synthetic enquiries spanning clear implementation, paid discovery, AI guardrails, vendor configuration, weak budget, sensitive uploads, unclear authority and no fit. Apply the current routing rules and explain ambiguous outcomes.

### 03-06 | Finish follow-up templates

Review the existing message sections and draft a consistent request acknowledgement, information request, recommendation, no-fit response, no-show follow-up and close-the-loop message. Align response promises with confirmed operations and keep ongoing nurture permission separate.

### 03-07 | Create a proposal completeness check

Using proposal requirements and approved offer boundaries, draft a checklist for scope, deliverables, assumptions, prerequisites, exclusions, effort, private fee, payment, acceptance and data handling. Mark unapproved commercial or legal fields rather than filling them with guesses.

### 03-08 | Prepare a Sales-to-Delivery handoff

Create a one-page handoff containing the named workflow, buyer authority, baseline, agreed scope, access dependencies, acceptance criteria, commercial status and next gate. Test it with a synthetic opportunity and expose anything Delivery would need to ask again.

### 03-09 | Specify end-to-end acceptance tests

Extend process section 13 to test valid leads, invalid input, duplicate/retry handling, spam, referral permission, inbox failure, pipeline ownership, booking and backup response. Define observable pass evidence; a mock reference or opened calendar link cannot pass receipt or booking.

### 03-10 | Review the first outreach cohort

Using actual de-identified pipeline results I provide, analyse response, qualification, product route, proposals, wins/losses and follow-up delays. Show denominators and missing evidence. Recommend one change to audience, message or process without treating small samples as proof.
