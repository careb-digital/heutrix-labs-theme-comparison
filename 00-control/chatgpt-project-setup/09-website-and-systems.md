## Ten prompts

Run one prompt per outcome-focused chat. The heading provides a suggested chat title. Each prompt uses this Project's instructions and sources. Complete dependent owner decisions before treating the resulting drafts as approved or live.

### 09-01 | Reconcile website release sources

Use LEAD-MAGNETS and the project-path inventory to map baseline, copy-comparison and refined sites to their roots, branches and recorded releases. Identify which records are stale and what must be verified before choosing a primary production site.

### 09-02 | Prepare the live-provider implementation brief

Translate Sales' approved lead-flow decision into a bounded Codex brief for the selected site. Specify provider contract, server/client responsibilities, validation, permission, failure recovery, receipt evidence and tests. Keep mock mode until the real connection passes verification.

### 09-03 | Specify calendar handoff behaviour

Using the approved booking rules, define the transition from request mode to calendar handoff. Cover timezone, availability, cancellations, mobile return path and confirmation semantics. A calendar-link click must not count as a booking.

### 09-04 | Audit form states and permissions

Review the supplied integration and form code for demo labelling, required permissions, referral handling, optional result sharing, oversized drafts, retry and failed receipt. Produce actionable findings tied to observed code; do not infer production behaviour without testing.

### 09-05 | Test interactive and workbook parity

Compare each interactive resource with its supplied workbook and guide. Focus on missing answers, score thresholds, control overrides and the documented AI Guardrails blank-answer issue. Produce a test matrix and versioned correction plan for any confirmed discrepancy.

### 09-06 | Create release acceptance criteria

Prepare a focused test plan for the selected website covering routes, mobile, keyboard access, downloads, hashes, redirects, 404s, permissions, failure paths and genuine lead receipt. Separate browser checks, provider checks and owner approvals.

### 09-07 | Resolve domain and indexing decisions

Review the deferred H6 technical SEO note and current comparison-release controls. Draft a primary-domain decision memo covering canonical URLs, redirects, robots, sitemap, social metadata and genuine HTTP 404s. Keep comparison sites' purpose explicit.

### 09-08 | Define privacy-safe measurement implementation

Translate the approved Marketing measurement brief into minimal event definitions and acceptance tests. Separate resource views, download attempts, requests received and bookings confirmed. Identify notice or provider changes needed before enabling tracking.

### 09-09 | Plan maintenance and recovery

Create an operating checklist for domain ownership, deployment access, dependency updates, provider failures, alerts, backups, rollback and receiving-inbox health. Use accountable-role placeholders and evidence-based service expectations.

### 09-10 | Prepare source consolidation handoff

Draft a bounded Codex task to reconcile approved changes across the selected website source and release copies. Include exact paths, preservation rules, comparison evidence, tests and unresolved owner decisions. Preserve nested report histories and do not authorise blind merges or deployment.
