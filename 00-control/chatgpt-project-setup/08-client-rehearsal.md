## Ten prompts

Run one prompt per outcome-focused chat. The heading provides a suggested chat title. Each prompt uses this Project's instructions and sources. Complete dependent owner decisions before treating the resulting drafts as approved or live.

### 08-01 | Define the synthetic engagement

Create a fictional disability-provider intake workflow with a bounded problem, sponsor, roles, baseline, constraints and success criteria. Use invented non-identifying records. Map the scenario to all six client-template stages and state which policy decisions remain unresolved.

### 08-02 | Rehearse contract and start gates

Populate a synthetic stage-01 checklist for scope, authority, approved terms, payment, data schedule and start conditions. Mark missing approvals as simulated or unresolved. Show why an incomplete start gate must prevent production work.

### 08-03 | Rehearse safe client inputs

Design synthetic stage-02 inputs, access requests and information classification. Test an unnecessary sensitive field and a credential accidentally included in a sample. Show the safe handling path and what should never enter the shared repository.

### 08-04 | Build the working papers

Create a compact stage-03 current-state map, bottleneck log, baseline plan, decision record and future-state proposal for the same fictional engagement. Maintain traceability from each problem to a proposed change and acceptance criterion.

### 08-05 | Run draft deliverable review

Prepare a synthetic stage-04 review pack and simulate conflicting feedback from an operator and sponsor. Separate clarifications, defects and scope changes. Record decisions and version status without treating every suggestion as an approved requirement.

### 08-06 | Test user acceptance

Execute a tabletop of the agreed synthetic acceptance cases, including missing data, duplicate work, absent owner and permission failure. Record expected versus observed simulated results, failures and retests. Do not present tabletop evidence as a software execution test.

### 08-07 | Rehearse change control

Introduce a second workflow and extra integration halfway through the fictional project. Apply the proposed change process, show effort/capacity/commercial dependencies and draft the decision request. Keep the original bounded scope intact unless explicitly changed.

### 08-08 | Prepare an issued handover example

Create a synthetic stage-05 handover index with accepted version, admin guide, user guide, limitations, ownership, licences, dependencies and support dates. Mark issuance as simulated and identify unresolved real-world release gates.

### 08-09 | Rehearse closeout

Walk the fictional engagement through stage 06: acceptance evidence, access removal, export, retention/deletion, unresolved defects and stabilisation ownership. Include proof required for each action and a failed-access-removal scenario.

### 08-10 | Report rehearsal gaps

Review all six stages and produce a prioritised defect list for Delivery, Legal, Sales, Company and Finance. Distinguish template omissions from unapproved policies and untested technology. Define retests and a clear go/no-go recommendation for the rehearsal only.
